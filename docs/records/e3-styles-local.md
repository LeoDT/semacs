# E3 文本样式与高亮合成本地验证

E3 本地实现、一次集中审查及修复后的记录；不表示真实环境或阶段收尾通过。此前失败保留于 [首版排版性能记录](e3-typography-probe.md)。行为与配置分别见 [E3 契约](../emacs-fidelity.md#阶段-e3文本样式与高亮合成)、[主题配置](../scripting.md#主题与命名样式)。

## 身份与边界

- 基于 `138995b31a615833e04a729e8d619c829b9667c4` 的未提交工作区。对照基线是该 HEAD，即 E2 加已完成的日常编辑增强，不把它混称为 E2 实现提交本身。
- 最终产品 / 测试 / example / 类型声明差异的 SHA-256 为 `4e23b055c550f2a90124c55291431789552a3e5a583ca68e9b39b6764630c2a5`。合并输入为 `git diff -- src tests examples types`，再按 `LC_ALL=C sort` 的未跟踪路径顺序追加这些目录下各文件的 `git diff --no-index /dev/null PATH` 输出。文档不计入这个源码身份。
- 全部测量都是本地 release、TestPlatform / NoopTextSystem 的 CPU 流程；字体敏感测试另用纯确定性测试后端，不读取系统字体、不启动桌面、不使用 GPU / 平台 IME。
- 没有放宽性能预算，没有以固定字宽、关闭换行或取消完整候选行校验换取通过。

## 同环境对照与成本定位

用户确认后，将 HEAD 和 E3 首版各复制到 `.pi/tmp/e3-ab/`，用相同诊断 harness 测 mixed 8,388,648 字节正文，各三轮。harness 只增加明确样本选择和当前可见几何完整性断言，不修改基线排版行为。

| 版本 | 首次正文及当前可见几何（三轮，ms） | 全文布局 ready（三轮，ms） |
|---|---|---|
| HEAD / E2 基线 | 0.363–0.476 | 133.696–135.511 |
| E3 首版 | 0.429–0.729 | 515.705–598.061 |

两侧第一帧的可见行均已完成匹配 shaping，故本组首次响应与首次可见几何在同一帧观察到；不是用全文 ready 冒充交互等待，也不外推为原生屏幕响应。

有效对照二进制 SHA-256：基线 `5d0a57b896d0c6d4fc47f9c2fa2b26e0aacec2c0474e92e168cfeede9e882ea6`，首版 `6d7f667215ba4c5211efd6390b0ea32bdb4343cb2845d38e476003ca4ca9a4d3`。早期共享 target 的两个临时包曾得到相同二进制摘要，发现后排除该组，不作为对照证据；改用不同诊断 package 名称重编译，并核对两份摘要不同。相同依赖仍复用原 target，不并行运行测量。

临时计时探针观察到首版一次 mixed 初始完整布局约 150,146 次候选校验、155,633 次完整片段 shaping；嵌套计时中字体 run 构建约 128 ms，shape_line 约 167 ms。计时有额外开销，父子区间不能相加，不据此报告精确独占成本比例。相关源码检查与分步诊断确认：

- 无局部字体变化时仍重复遍历字素构建同一字体 run；现使用统一字体快速路径，不跳过字形测量。
- 非 ASCII 宽度缓存每次命中仍构造拥有字符串的键；改为按字体属性分组后借用字符串查找，缓存命中不再分配该键。
- 原有 256 次测量的缓存上界没有包含新增候选行 shaping，造成 WindowTextSystem 在全文扫描时持续积累唯一行布局；现所有字形测量共用有界入口，直接使用与绘制 shape_line 相同的 layout_line 字形布局 API。
- 修复了默认属性强行覆盖基础字体粗体 / 斜体的问题：未指定继承，显式 normal / false 才取消；这不是省略字体差异来加速。

优化后仍比旧基线慢，精确候选行测量有真实成本；不能宣称已恢复 E2 吞吐量。临时诊断和所有旧失败保留，不将它们当成最终验收批次。

### 集中审查与修复

仅调用一次 reviewer。两项 P2 均已由主代理修复并验证，没有追加审查：

1. 后台字体重排尚未完成时，旧视口锚点可能覆盖后续显式跳转 / recenter。现显式导航、相关指针 / 滚动及 point reveal 路径取消该锚点；回归在完整索引仍 pending、视口远离预览范围时执行 beginning-of-buffer 与 recenter，并核对后台完成后 point / scroll / cursor。
2. 默认 NoopTextSystem 忽略字体描述符及字体 run，原有几何测试不能证明字体差异正确。新增确定性 `StyledTextSystem`：四种字体有不同 advance，模拟 AV 上下文扩张及 fi 连字收缩。测试直接断言精确候选边界、字体导致的软换行变化、tab phase / 位置、命中和平台适配器返回的 UTF-16 / 预编辑 bounds 数值，而不只是检查缓存已换。

该后端验证字体差异下的模型一致性，不模拟所有真实字体、HarfBuzz、fallback 或实际 IME 协议，不替代宿主证据。

## 正式 headless 性能回归

新批次 `.pi/tmp/e3-acceptance-01/`：六类约 8 MiB 正文，每类三轮，独立进程按样本顺序执行，无构建或其他测量并行。perf_view 已支持严格 SHAPES 选择，并在每个阶段完成测量时立即检查既有预算；超限、非有限或负数立即退出。样本选择与预算检查均有单元测试，不重现首批工具仅输出 CSV 的停止局限。

18 行 perf_view 的最坏值如下；各轮均满足门限，不用跨轮平均值掩盖失败：

| 指标 | 最坏值（ms） | 既有预算（ms） |
|---|---:|---:|
| 初始首次正确可见布局 | 0.542 | 2 |
| 初始全文 ready | 292.720 | 300 |
| 滚动 | 0.214 | 1 |
| 改宽 ready | 291.313 | 300 |
| 改字体 ready | 293.202 | 300 |
| 稳定 forced frame / empty draw 均值 | 0.062 / 0.062 | 各 0.25 |
| 插入 / 后删 / 换行 / 合行 front | 0.534 | 各 2 |
| 插入 / 后删 / 换行 / 合行 ready | 267.086 | 各 300 |

同批 perf_m1 共 540 行，内置预算检查通过：同步动作最高 0.438 ms、front 最高 0.576 ms、ready 最高 238.926 ms。其 1024 键未等待后台输入段仍只代表有界前台及末键恢复，不表示每个被取代版本都完成全文布局，也不代替原生持续输入。

集中审查后产品仅修复显式导航取消字体锚点；新增敏感测试后端不进入产品构建。随后重编译 release，在新的 `.pi/tmp/e3-acceptance-after-review/` 复核 mixed / single-ascii 各三轮，共六行，全部门限满足：初始 ready 最高 279.613 ms、改宽 / 字体 ready 最高 280.156 / 283.028 ms、输入 front / ready 最高 0.368 / 273.102 ms。两批原始 CSV 和 stderr 均保留，独立离线重新核对每行字段与预算；六类完整批次和审查后代表性复核的覆盖不混称。

### 语法与匹配排版独立基线

perf_syntax 五类各三轮完成。cold 的语法 + 布局就绪区间：Rust 8 MiB 为 1645.431–1780.357 ms；长 raw string 8 MiB 为 195.173–197.912 ms；Markdown 256 KiB 为 212.571–219.734 ms；HTML 256 KiB 为 78.462–79.595 ms；TSX 256 KiB 为 60.582–72.873 ms。包括插入、undo / redo、32 键 burst、主题切换与稳定绘制流程，文本 / point / 就绪断言通过。

这些是含解析的独立基线，不套用纯布局 300 ms 门限，不由命令退出成功推导原生或其他未定义预算通过。
