改宽 / 字体采用的首份保留或当前场景提交分别最高 **26.379 / 12.104 ms**，不是上表要求当前兼容布局的首次目标提交。单次 CPU draw 最大 **13.093 ms**。12 窗共 360 个稳定观察 tick 均无 draw；空白及缺失观察均为零，不据此报告 0 ms 帧或空闲功耗。

本批所覆盖动作的选中 view 既有预算与 draw / idle 要求均满足。32 次删除的同步动作最高 46.394 / 50 ms、首次提交最高 47.791 / 50 ms，虽未超限但余量较小，不以本轮成功推断无后续波动风险。

只统计已经 split 的双 view 阶段，全部就绪最高 **229.339 ms**，不能混入 boot 的单 view 375.729 ms。每个组合的逐轮聚合最大值如下：

| 上下 / mixed | 183.339 | 183.622 | 184.510 |

20 条数据的 selected-ready 与 all-ready 不同。例如左右 mixed 第三轮 32 次删除分别为 **46.604 / 204.259 ms**；不能用较早的前台就绪替代全部 view 就绪。聚合没有新增数值门限，本表不是“聚合预算通过”结论。

## 结论与未测边界

本批宿主、实际尺寸下，两方向 × 两个代表样本各三轮的选中 view 定向性能检查通过，并建立了独立的同帧聚合基线；不重复功能 / IME 人工清单。

- 其他四类原生样本、其他字体 / 尺寸、嵌套 split、M1 长时间持续输入及 M2 文件 / 保存矩阵未在本批复测。
- 使用正式 AppShell 路由内的合成 GPUI 输入；没有 OS 注键、输入法操作或截图，不作为真实键盘 / IME 时延证据。
- 字体阶段使用 view 设置入口，不代表正式配置命令完整传播的端到端时延。
- CPU / 平台提交不是 GPU 执行或实际屏幕呈现；metadata 的 restored 不作为新的焦点恢复功能验收。
- 两个原生代表样本不能关闭先前六类 headless 双 view 聚合约 350 ms 的风险；平台 / 调度与尺寸口径不同，不静默改预算或据此解释为相同条件下加速。
- 本轮定向通过不自动宣布阶段 C 整体完成。后续风险收束及阶段状态以[实施计划](../plan.md)为入口，新增真实环境测试仍须另行同意。
