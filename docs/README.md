## 维护原则

- 文档记录产品契约和关键、难以回退的技术决策；实现结构、配置、算法细节与测试覆盖由代码维护。
- 每项契约只保留一份正文，其他位置引用，不复述；不维护跨文档的“当前能力”清单。
- 实现进度只在计划中维护；已完成阶段的实测与验收作为固定归档，不写成持续更新的实现说明。
- 外部观察、历史实测与许可证材料不是代码镜像；保留理解结论所需的环境、证据边界和来源，不保留过程流水账。
- 需求或验收标准不等于产品已实现。新增保真度差异、平台依赖调整或输入策略变动须先确认；真实环境测试须另行获得同意。
