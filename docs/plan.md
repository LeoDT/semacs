# 实施计划

里程碑按可验收行为划分，不按工期估算。此处只维护阶段与交付边界，不维护模块 / 测试覆盖清单。
产品契约见 [Emacs 保真度](emacs-fidelity.md)，性能约束见 [性能预算](performance.md)。

## 已完成阶段

- **R0**：产品范围、组件选择、许可边界、应用外壳与文件读取基础。
- **R1**：最小正式编辑切片及输入 / 显示性能基线。验收结论、实测和未测限制见 [固定归档](records/r1.md)。
- **M1**：键位、共享编辑语义与历史；持续输入 / 完整命令链性能按用户确认口径验收通过，证据与未测边界见 [M1 记录](records/m1-performance.md)。
- **M2 / M3**：minibuffer、文件与 buffer 管理及 v1 范围内保真度 / 性能收尾验收通过，宿主 perf、真实 IME 代表性复测与人工闭环已核对；证据与保留限制见 [验收记录](records/m2-m3-local.md#阶段最终结论)。

- **A**：显示设置与方块光标完成；本地检查、用户人工 / IME 确认及宿主定向性能复核通过，范围和未测边界见 [验收记录](records/a-display-local.md)。

## M1 键位、编辑语义与历史

状态：本阶段已完成。用户已确认持续输入中过期目标不要求完成完整布局、停止输入后的最终版本须在 300 ms 内完整就绪的口径；验收通过，保真度差异及未测边界保留。证据见 [M1 记录](records/m1-performance.md)，不代表 M2 文件 / 完整读入或 M3 全量验收已完成。

- 自有分层 keymap、无超时前缀、命令注册与统一目标路由；处理绑定冲突和 undefined / self-insert 分类。
- 基础 motion、翻页、换行 / 基础缩进、删除、kill / yank、mark / region 与 quit。
- 历史分组、保存点与 marker，undo / redo 经同一编辑入口回放。
- 正文与 minibuffer 共用最小编辑语义，但不提前完成完整读入 / 补全会话。
- 将组合屏障、只读与 pending 前缀约束接入正式命令及直接输入路径。

验收重点：纯键盘基本编辑，真实命令链与 Emacs 参照对比；补测长时间持续输入及完整命令链的同步更新、首次提交与完整布局就绪延迟，维持已有性能预算。

## M2 minibuffer、文件与 buffer 管理

状态：本阶段按既定 v1 范围验收通过。首屏准备阻塞 draw 的问题已定位并修复，本地回归、宿主正式性能矩阵、真实 IME 代表性复测，以及用户按文档完成的纯键盘文件闭环、正文 / minibuffer IME 与 OS 关闭均已核对。证据、实际尺寸与保留限制见 [验收记录](records/m2-m3-local.md#阶段最终结论)，复测步骤见 [宿主验收](acceptance.md)，不原样重跑既有目录。

- `M-x`、文件打开 / 保存 / 另存、buffer 切换 / 关闭与退出。
- 命令名 / 路径 / buffer 名基础补全，prompt 保护、确认 / 取消与焦点恢复；覆盖、外部修改、kill 与退出等普通确认走 minibuffer 查询会话。
- 多 buffer 独立状态及共享 kill ring；输入会话切换不污染其他目标。
- 无损文件往返、实际保存点、失败处理、覆盖确认和 dirty 数据丢失确认；OS 窗口关闭等无法可靠进入 minibuffer 的平台事件可使用窗口级确认，但须安全默认取消并登记差异。

验收重点：无鼠标完成打开 → 编辑 → `M-x` → 保存 → 切换 → 退出；独立断言磁盘字节与失败安全，不以空保存命令或仅设置 modified 代替实际保存。

## M3 v1 保真度与性能验收

状态：本阶段按既定 v1 范围验收通过。范围内键位 / 命令名、编辑、历史、跨 buffer、minibuffer、IME 与退出的既有回归 / Emacs 参照和本轮宿主补测已汇总，性能按既有预算及实际测量边界核对；见 [最终结论](records/m2-m3-local.md#阶段最终结论)。
范围内 F1 按已覆盖用例核对，F2 / F3 沿用已登记差异，无新增发布豁免；不扩大 v1 范围，也不将未覆盖平台或未测指标记为通过。

## 后续阶段

以下为已确认的推进顺序，不是已展开的实施规格。长期只维护阶段目标与依赖，进入阶段后再确认具体交互及验收；核心 / 脚本边界见 [D26](decisions.md#d26-rust-核心与脚本扩展)。

| 阶段 | 交付边界 |
|---|---|
| **A：显示设置** | Rust 字体 / 字号设置模型、字号命令和方块光标；不为持久配置先建一套临时静态格式。 |
| **B：候选式 minibuffer** | 分离输入、候选与选中项，提供无输入候选、纵向导航及注释展示；覆盖现有命令 / 文件 / buffer 读入。 |
| **C：buffer / view 与 split** | 整理共享 buffer 与 view 的所有权，实现 split；明确 window-point、mark、焦点和多 view 输入路由。 |
| **D：最小脚本接入** | rquickjs、JS 用户配置、自定义键位与统一命令注册；以一个简单文本变换命令验证宿主 API 和执行边界，不先建设包管理器。 |
| **E：tree-sitter** | 先打通一种语言的 Rust 增量解析与高亮，按实际需求增加查询等脚本接口；不是 D 的前置条件，也不同时扩展为 LSP / 完整语言平台。 |
| **F：diff → magit** | 先 diff 查看，再推进 magit 风格 git 工作流；复用编辑语义，按需增加进程、section 与 transient 等原语，不预建通用 UI 框架。 |

C 在稳定脚本 API 前完成，避免把当前单 view 所有权固化为外部契约。D 的前提是状态归属明确、编辑入口统一、异步结果可校验且扩展不能阻塞热路径，不是提前实现所有未来核心能力。

### 阶段 A：显示设置

状态：本阶段按既定范围完成并验收通过。本地检查、六类各三轮 headless 回归、用户基本外观 / 交互及改字体 / 字号后的正文与 minibuffer IME 确认，与 mixed / single-ascii 各三轮宿主定向性能结果已核对；未扩大到其他样本的本轮原生复测、GPU 执行或完整新配置命令时延。证据与未测边界见 [验收记录](records/a-display-local.md)，不再原样重跑本批。目标先解决有无，不建设完整外观 / 交互系统；行为契约见 [显示设置](emacs-fidelity.md#7-显示设置)。

按两个可独立检查的切片推进：

1. **字体 / 字号设置**：建立共享设置来源，接入命令及已有 / 新建正文和 minibuffer，处理行高、minibuffer 高度与布局失效。
2. **方块光标**：分离视觉光标与平台输入几何，处理字形簇、TAB、行尾及预编辑显示，保持已有编辑语义。

每个切片随实现补充回归，最后完成阶段检查；验收沿用既有字体变化 / 输入 / 布局预算，核对非空白显示、坐标兼容、状态不受显示设置影响及字号边界。真实字体绘制与 IME 桌面验证另行征求同意，未做前不记为通过。

B 的 RET / TAB、候选导航、空输入默认项与新路径接受规则在进入该阶段时确认，再更新保真度契约，不以本路线图替代当前行为。D 的配置失败 / 重载语义、权限和运行时约束届时另定，不默认承诺完整模块热重载。

isearch、`M-y`、`C-u`、occur 等其他增强保留为未排期需求，按实际需要另行确认，不因脚本接入自动扩大范围。

## 完成标准

- 每个实现阶段通过 `cargo test --all-targets`、`cargo clippy --all-targets -- -D warnings`、`cargo fmt --check`；日常小改动按影响做必要检查，不把里程碑验收机械套到每次配置或文档编辑。
- headless 回归不能替代真实 Wayland / IME 证据；需要真实环境的验证须单独获得同意，未测不记为通过。
- 任务进度放 `.pi/tasks/`，临时验证产物放 `.pi/tmp/`；正式测试不依赖临时目录中的唯一实现。
