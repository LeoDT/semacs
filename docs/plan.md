## 当前阶段 E2：多语言语法支持

### 目标与边界

- 将 Rust 专用语法路径整理为小型语言注册表和通用解析机制；保留 Rust 支持，增加 JS / JSX / TS / TSX / Markdown / HTML / CSS。
- grammar 通过 Cargo 依赖原生内置，接受增加语言后重新编译。语言定义集中描述身份、文件关联、grammar 与查询；不预建独立语言包格式、动态库 / WASM 加载器、安装工具或 JS 语言 API。
- Markdown 目标包含块级、行内高亮及本轮已注册语言的围栏代码块高亮；未知代码块语言保持普通代码文本。JSX / TSX 由对应 grammar 直接解析，不作为跨语言注入实现。
- 沿用后台增量解析、buffer 共享、快照 / 语言身份隔离、失败降级和仅前景色高亮，不改变文本、历史、布局及输入坐标。不包含 Markdown 预览、粗体 / 斜体 / 字号变化、LSP、格式化、语言专用缩进或完整插件平台。
- 讨论依据、上游源码身份与结构建议见 [E2 工作稿](work/e2-languages.md)。后续动态语言支持与 LSP 只用于检查边界，不是本阶段交付或已排期任务。

### 验收目标

- 约定文件类型正确选择语言；成功另存跨语言切换时不复用旧语言语法树或应用迟到高亮，Rust 行为不回退。
- 覆盖各语言代表性语法、JSX / TSX 标签与表达式，以及 Markdown 块级 / 行内 / 围栏代码；查询组合与 capture 样式适配有明确测试。
- 编辑、undo / redo、共享 view、预编辑投影与语法失败降级保持正确；子语言解析同样可取消，结果绑定当前文本与语言身份。
- 按影响执行静态检查、单元测试与 headless 回归；关注多层解析就绪成本，不放宽既有性能预算。真实环境验证须另行征得用户同意，未测不记通过。

### 实现前需细化

- 固定依赖版本、grammar ABI、查询组合顺序、文件后缀 / 语言别名、capture 映射及第三方许可；本次源码阅读不等于 Cargo 依赖和查询兼容性已经验证。
- 选择 Markdown 上游双层 parser 封装或统一语法分层实现；明确子语言范围、增量失效、取消、嵌套 / 资源边界与高亮覆盖规则，避免为少数语言预建通用插件框架。
- 明确 HTML 的 script / style 是否纳入本轮，以及其余注入规则的取舍；不因上游提供 injections 查询而默认承诺全部执行。实现前整理 E2 行为契约，保留 E1 冻结范围及历史记录。

## 已知问题与未排期事项

- **多 view 聚合性能观察（非阻塞）**：六类 headless 双 view 全部 ready 曾约 350 ms；它与旧单 view / 选中 view 的 300 ms 指标不同，聚合没有另定数值门限，不能判作预算超限或自动产生补测任务。用户已接受保留该观察并收尾阶段 C。后续仅在出现实际响应问题或确认新预算时再考虑定向分析；不外推两个原生代表样本为六类全覆盖，也不安排追加测试。
- **日常编辑增强**：isearch、`M-y`、`C-u`、occur 等未排期，实际需要时再确认优先级与范围。
- **自动保存与备份**：保留为数据安全增强需求，尚未明确策略且不属当前范围；排期前先确认触发、写入位置与恢复行为。
