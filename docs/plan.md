# 实施计划

里程碑按可验收行为划分，不按工期估算。本文是跨会话工作的统一入口；维护与归档规则见 [文档说明](README.md#维护规则)。范围见 [需求](requirements.md)，行为见 [保真度契约](emacs-fidelity.md)。

## 当前阶段：B 候选式 minibuffer

状态：整体方向已确认，具体交互待设计确认，尚未开始实现。

- **目标 / 边界**：提供无输入候选、纵向选择及注释展示，覆盖现有命令 / 文件 / buffer 读入；分离输入、候选集合、选中项和显式接受动作，不同时引入脚本运行时或完整模糊匹配 / 历史搜索系统。
- **先确认**：RET / TAB、候选导航与空输入默认项；进入目录、接受候选与接受不存在的新路径如何区分；候选更新与 IME 预编辑如何配合。
- **验收边界**：明确各类读入的键盘闭环，保持 prompt 保护、取消、原目标 / 焦点恢复和迟到结果隔离；受影响输入 / 布局仍遵循既有契约及 [性能预算](performance.md)。新增候选交互的具体验收在编码前确认，不自行扩大预算含义。
- **下一步**：检查现有读入 / 补全模型，提出最小交互方案；确认后更新行为契约，再进入实现和必要的定向回归。不预先展开后续阶段的完整接口。

## 后续阶段

以下只维护顺序与依赖，不是已经展开的实施规格；核心 / 脚本边界见 [D26](decisions.md#d26-rust-核心与脚本扩展)。

| 阶段 | 交付边界与前置条件 |
|---|---|
| **C：buffer / view 与 split** | 整理共享 buffer 与 view 所有权，实现 split；先明确 window-point、mark、焦点和多 view 输入路由，在稳定脚本 API 前完成。 |
| **D：最小脚本接入** | rquickjs、JS 配置、自定义键位和统一命令注册，以简单文本变换命令验证边界；届时确认配置失败 / 重载、键位覆盖 / 取消 / 冲突、权限、执行与资源约束，不先建设包管理器或承诺完整模块热重载。 |
| **E：tree-sitter** | 先打通一种语言的 Rust 增量解析与高亮，再按需增加查询等脚本接口；不是 D 的前置条件，不同时扩展为 LSP / 完整语言平台。 |
| **F：diff → magit** | 先 diff 查看，再推进 git 工作流；按实际需求增加进程、section 与 transient 原语，不预建通用 UI 框架。 |

D 的前提是状态归属明确、编辑入口统一、异步结果可校验且扩展不能阻塞热路径，不是提前实现所有未来核心能力。
