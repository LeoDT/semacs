## 当前阶段：C buffer / view 与 split

状态：待设计确认，尚未开始实现。阶段 B 已按已确认范围验收完成，见 [宿主人工验收](records/b-minibuffer-host.md)。

- **目标 / 边界**：整理共享 buffer 与 view 所有权，实现 split 与同 buffer 多 view；在稳定脚本 API 前明确状态归属，不同时展开脚本运行时或通用窗口管理框架。
- **先确认**：window-point、mark / active 的归属与跨 view 行为；split 的方向 / 键位、初始状态与焦点；关闭 view 与 buffer 生命周期的关系；多 view 的输入、pending 前缀和 IME 路由。
- **验收边界**：共享文本、history、modified 与保存身份不分叉；viewport / scroll / 布局保持 view 隔离，同 buffer 的编辑结果正确传播。输入与异步结果仍绑定目标 / 版本，既有 minibuffer 取消与原目标恢复不回退；受影响热路径遵循既有性能预算。
- **下一步**：按需检查当前状态归属与输入路由，提出最小交互 / 所有权方案，先向用户确认，再更新契约并实现。不预先固定未来脚本接口或擅自决定未确认的 split 行为。

## 后续阶段

以下只维护顺序与依赖，不是已经展开的实施规格；核心 / 脚本边界见 [D26](decisions.md#d26-rust-核心与脚本扩展)。

| 阶段 | 交付边界与前置条件 |
|---|---|
| **D：最小脚本接入** | rquickjs、JS 配置、自定义键位和统一命令注册，以简单文本变换命令验证边界；届时确认配置失败 / 重载、键位覆盖 / 取消 / 冲突、权限、执行与资源约束，不先建设包管理器或承诺完整模块热重载。 |
