# 技术决策

只记录影响长期边界的选择及理由，不维护版本号、配置参数、模块清单或实现进度。
既有 D 编号保留以兼容引用；产品行为只在 [Emacs 保真度](emacs-fidelity.md) 定义，范围只在 [需求与范围](requirements.md) 定义。

## D1 依赖与构建

复用 gpui-kit 所用的同一套 GPUI，不并存另一套 GPUI 类型或运行时，避免平台对象与输入协议分裂。
本地参考仓库不成为构建依赖；依赖调整不通过修改 registry 缓存实现。具体版本与构建参数以 Cargo 文件为准。

## D2 平台

平台支持目标见 [平台与交互边界](requirements.md#平台与交互边界)；支持目标不等于验收证据。

## D3 键位

不混合 Emacs 与 CUA 编辑模型，避免 `C-c` / `C-x` 前缀与复制 / 剪切冲突。
具体键位与输入分类见 [键位解析约定](emacs-fidelity.md#3-键位解析约定)。

## D4 命令分发

自有 keymap、前缀解析和命令路由接管编辑目标，GPUI action 不作为主命令系统。
正文与 minibuffer 使用同一套命令语义；自插入、IME 等直接输入路径也受目标、pending 前缀与只读约束，不能成为绕过命令规则的第二入口。

## D10 工程结构

保持单 crate 和少量职责模块，不预建插件机制、可插拔后端或独立发布工程；当前没有需要这些边界的产品需求。

## D11 命令注册表

keymap、`M-x` 与后续帮助共用唯一的命令注册来源，避免命令名和执行入口各自漂移。

## D12 外观

不模拟 Emacs 外观；外围交互与主题交给 gpui-kit，正文编辑视图不交给通用输入控件。
产品可观察的 mode line / echo 要求见 [保真度分级](emacs-fidelity.md#2-保真度分级)。

## D13 键位配置

v1 默认键位由程序定义；用户配置格式和覆盖机制延后，避免把尚未稳定的内部模型固化为外部兼容承诺。

## D16 编辑历史与保存点

历史由自有编辑模型控制，不依赖 UI 控件历史；回放经过唯一 Edit 入口，但不重复登记为新用户编辑。
采用线性 undo / redo，不复刻 Emacs undo 环或 undo-in-region。分组、point 与 modified 的完整契约见 [历史与保存点](emacs-fidelity.md#历史与保存点)。

## D17 IME 命令屏障

采用“先完成组合，再执行命令”的交互，而不是在命令执行时猜测提交或取消意图。
这是批准的产品策略，不随实现能力自动放宽；具体行为见 [IME 与生命周期](emacs-fidelity.md#ime-与生命周期)。

## D18 mark 与 marker

mark 采用随已提交编辑移动的 marker 语义，不是固定 offset；在唯一 Edit 入口统一调整，避免各命令维护不同规则。
位置、激活状态与历史回放的契约见 [mark 与 region](emacs-fidelity.md#mark-与-region)。

## D19 关闭与失焦

用户已接受现有平台输入协议的边界：丢弃仍 marked 的文字，不撤销平台已明确提交的正文替换；不为实现“整次组合回滚”修改 GPUI。
取消、unmark、失焦及关闭确认的行为见 [IME 与生命周期](emacs-fidelity.md#ime-与生命周期)。

## D20 文件格式

文件适配以无损往返为原则；不猜测编码、不有损解码、不静默转换不支持的换行格式，避免“打开再保存”破坏原文件。
支持范围及失败语义见 [文件与退出](emacs-fidelity.md#文件与退出)。

## D21 自有 editor

semacs 自有文本编辑模型、显示映射、视图、输入适配和 buffer / window / mode / command 语义。
GPUI 只提供窗口、平台输入 / IME、字体 shaping 与绘制，gpui-kit 只承担外围 UI 和主题；这样编辑语义不受通用控件内部状态约束。

长期边界：

- 已提交正文是权威状态，预编辑是独立临时状态；命令、平台提交、补全和历史回放均经过唯一 Edit 入口。
- 输入绑定原目标及会话，异步布局绑定目标及快照身份；迟到结果不能按当前焦点重新解释或覆盖新状态。
- 布局未兼容当前显示文本时，不提供错误的 caret、命中或 IME 坐标；显示投影的边界不替代 Emacs 字符运动语义。
- view 拥有 viewport、scroll 与布局。单 view 阶段 point / goal column 可归 Buffer；增加 split 前必须另定 window-point 与焦点路由，不把现有分离当作多 view 已完成。
- 昂贵全文工作不能阻塞前台；区分临时预览与最终精确布局，不以截断正文、关闭软换行或漏绘换取性能。具体算法与阈值由代码维护。

## D22 源码复用与许可

选择性复用 Zed 的纯文本组件，不整体引入 Editor、text::Buffer、MultiBuffer、language、project 或 Zed 运行时，也不维护外部 fork；这些系统的协作与项目模型超出产品需求。
优先调用现有 GPUI API；只有实际需要时才继续提取算法，依赖闭包显著扩大时先审查。

用户接受 GPL-3.0-or-later 组件及其对整合作品分发的要求。每批导入须核对实际文件许可，区分复制 / 改编与设计参考，保留版权、适用许可证 / NOTICE，并记录来源、commit、路径、本地修改与测试。
不能将 GPL 源码重标 MIT；Apache 组件保留自身许可，自有代码授权不覆盖第三方代码。
代码在本仓库维护，按已验证缺陷选择性吸收上游修复，不持续追随上游。

实际来源和本地修改只在 [THIRD_PARTY.md](../THIRD_PARTY.md) 维护；分发要求见 [LICENSE](../LICENSE)。二进制发布前仍须审核依赖归属材料和相应源码。

## D23 R1 验收范围与后续测量

R1 的用户确认、证据组合及未测指标只在 [R1 验收归档](records/r1.md#验收结论) 记录。
后续沿用 [性能预算](performance.md)，不调宽预算掩盖回退；阶段补测安排见 [实施计划](plan.md)。

## D24 缩进边界

缩进计算与编辑应用分离，复用统一 Edit / 历史入口；M1 只做无语言基础缩进，不预建 mode 或插件框架。后续语言缩进可基于 tree-sitter 的语法结构与语言规则，不以复刻 Emacs major mode 为前提。

新增保真度差异、平台依赖调整或输入策略变化须先确认；真实环境验证另行征求同意。
