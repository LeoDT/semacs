# 技术决策

只记录影响长期边界的选择及理由，不维护版本号、配置参数、模块清单或实现进度。
既有 D 编号保留以兼容引用；产品行为只在 [Emacs 保真度](emacs-fidelity.md) 定义，范围只在 [需求与范围](requirements.md) 定义。

## D1 依赖与构建

复用 gpui-kit 所用的同一套 GPUI，不并存另一套 GPUI 类型或运行时，避免平台对象与输入协议分裂。
本地参考仓库不成为构建依赖；依赖调整不通过修改 registry 缓存实现。具体版本与构建参数以 Cargo 文件为准。

## D2 平台

平台支持目标见 [平台与交互边界](requirements.md#平台与交互边界)；支持目标不等于验收证据。

## D3 键位

不混合 Emacs 与 CUA 编辑模型，避免 `C-c` / `C-x` 前缀与复制 / 剪切冲突。
具体键位与输入分类见 [键位解析约定](emacs-fidelity.md#3-键位解析约定)。

## D4 命令分发

自有 keymap、前缀解析和命令路由接管编辑目标，GPUI action 不作为主命令系统。
正文与 minibuffer 使用同一套命令语义；自插入、IME 等直接输入路径也受目标、pending 前缀与只读约束，不能成为绕过命令规则的第二入口。
命令声明所属作用域（编辑、应用、读入会话），键盘入口按层组合；应用与读入会话命令只向上返回请求，由所属层执行，不下放到编辑目标。

## D10 工程结构

保持单 crate 和少量职责模块；围绕已确认的脚本扩展需求建立边界，不预建通用插件框架、可插拔后端或独立发布工程。脚本边界见 D26。
窗口外壳负责所有权、命令路由与 GPUI 适配；读入规则、保存队列与关闭决策归对应领域模型，不通过拆文件继续把规则集中在外壳。保存完成后的关闭动作与退出流程互斥，不维护独立布尔标志的隐含组合；不为此引入通用 workflow 或 controller 框架。

## D11 命令注册表

keymap、`M-x` 与后续帮助共用唯一的命令注册来源，避免命令名和执行入口各自漂移。

## D12 外观

不模拟 Emacs 外观；外围组件由 gpui-kit 绘制，semacs 的命名样式与主题设置统一解析并映射到 gpui-kit 颜色，正文编辑视图不交给通用输入控件。正文默认字体随包提供 Lilex 的四个真实变体，通过现有 GPUI TextSystem 统一加载，避免依赖系统字体安装和通用族名解析；不为此引入另一套字体解析或布局后端。主题借鉴可理解的界面名称和切换操作，不引入 Emacs font-lock / 完整 face 机制或 elisp 兼容。
产品可观察的 mode line / echo 要求见 [保真度分级](emacs-fidelity.md#2-保真度分级)。

## D13 键位配置

默认键位由程序定义，用户键位配置遵循 D26 的脚本配置边界；覆盖、取消绑定、层级冲突及重载时 pending 前缀的处理见[阶段 D 契约](emacs-fidelity.md#阶段-djs-配置与文本变换)，不把内部 keymap 结构直接固化为外部接口。

## D16 编辑历史与保存点

历史由自有编辑模型控制，不依赖 UI 控件历史；回放经过唯一 Edit 入口，但不重复登记为新用户编辑。
采用线性 undo / redo，不复刻 Emacs undo 环或 undo-in-region。分组、point 与 modified 的完整契约见 [历史与保存点](emacs-fidelity.md#历史与保存点)。

## D17 IME 命令屏障

采用“先完成组合，再执行命令”的交互，而不是在命令执行时猜测提交或取消意图。
这是批准的产品策略，不随实现能力自动放宽；具体行为见 [IME 与生命周期](emacs-fidelity.md#ime-与生命周期)。

## D18 mark 与 marker

mark 采用随已提交编辑移动的 marker 语义，不是固定 offset；在唯一 Edit 入口统一调整，避免各命令维护不同规则。
位置、激活状态与历史回放的契约见 [mark 与 region](emacs-fidelity.md#mark-与-region)。

## D19 关闭与失焦

用户已接受现有平台输入协议的边界：丢弃仍 marked 的文字，不撤销平台已明确提交的正文替换；不为实现“整次组合回滚”修改 GPUI。
取消、unmark、失焦及关闭确认的行为见 [IME 与生命周期](emacs-fidelity.md#ime-与生命周期)。

## D20 文件格式

文件适配以无损往返为原则；不猜测编码、不有损解码、不静默转换不支持的换行格式，避免“打开再保存”破坏原文件。
支持范围及失败语义见 [文件与退出](emacs-fidelity.md#文件与退出)。

## D21 自有 editor

semacs 自有文本编辑模型、显示映射、视图、输入适配和 buffer / window / mode / command 语义。
GPUI 只提供窗口、平台输入 / IME、字体 shaping 与绘制，gpui-kit 只承担外围 UI 和主题；这样编辑语义不受通用控件内部状态约束。

长期边界：

- 已提交正文是权威状态，预编辑是独立临时状态；命令、平台提交、补全和历史回放均经过唯一 Edit 入口。
- 输入绑定原目标及会话，异步布局绑定目标及快照身份；迟到结果不能按当前焦点重新解释或覆盖新状态。
- 布局未兼容当前显示文本时，不提供错误的 caret、命中或 IME 坐标；显示投影的边界不替代 Emacs 字符运动语义。
- buffer 拥有共享 document、history、modified、文件 / 保存身份及 mark / active；view 拥有 point、goal column、scroll、布局与输入会话。编辑调整其他 view 的 point 而不触发自动滚动。阶段 C 的分割、焦点、关闭与输入路由行为见 [buffer 与 view 契约](emacs-fidelity.md#阶段-cbuffer-与-view)。
- 昂贵全文工作不能阻塞前台；区分临时预览与最终完整布局；全文索引用字体敏感的字素测宽，可见行与输入坐标使用精确 shaping，精度边界见 [E3 契约](emacs-fidelity.md#阶段-e3文本样式与高亮合成)，不以截断正文、关闭软换行或漏绘换取性能。具体算法与阈值由代码维护。

## D22 源码复用与许可

选择性复用 Zed 的纯文本组件，不整体引入 Editor、text::Buffer、MultiBuffer、language、project 或 Zed 运行时，也不维护外部 fork；这些系统的协作与项目模型超出产品需求。
优先调用现有 GPUI API；只有实际需要时才继续提取算法，依赖闭包显著扩大时先审查。

用户接受 GPL-3.0-or-later 组件及其对整合作品分发的要求。每批导入须核对实际文件许可，区分复制 / 改编与设计参考，保留版权、适用许可证 / NOTICE，并记录来源、commit、路径、本地修改与测试。
不能将 GPL 源码重标 MIT；Apache 组件保留自身许可，自有代码授权不覆盖第三方代码。
代码在本仓库维护，按已验证缺陷选择性吸收上游修复，不持续追随上游。

实际来源和本地修改只在 [THIRD_PARTY.md](../THIRD_PARTY.md) 维护；分发要求见 [LICENSE](../LICENSE)。二进制发布前仍须审核依赖归属材料和相应源码。

## D23 性能证据边界

预算及指标的唯一正文见 [性能预算](performance.md)，不调宽预算掩盖回退。历史用户确认、环境、实测与未测项由对应验收记录保留，不用旧版本的证据替代新代码验证；执行分工见 [验收流程](acceptance.md)。

## D24 缩进边界

缩进计算与编辑应用分离，复用统一 Edit / 历史入口；无语言基础缩进不依赖 mode 或插件框架。语言缩进可基于 tree-sitter 的语法结构与语言规则，不以复刻 Emacs major mode 为前提。

## D25 确认交互

普通覆盖、外部修改、kill dirty buffer 与退出确认使用 minibuffer 查询会话，复用读入会话的目标绑定、取消、焦点恢复和迟到结果隔离；不默认使用窗口级按钮确认框另建一套交互。
查询交互不能统一退化为整行读入：覆盖与退出保存用单键 y / n，kill 修改确认用单键 y / n / s；外部修改和最终退出确认要求完整 yes / no 后 RET。单键查询不回落到编辑 keymap，RET 不代表默认同意，C-g 始终可取消。
OS 窗口关闭等平台触发且无法可靠聚焦 minibuffer 的确认可使用窗口级 / 平台确认，但必须安全默认取消、保留取消后的正文与焦点，并作为已登记平台差异；该例外不得扩散为其他确认的默认实现。

## D26 Rust 核心与脚本扩展

Rust 负责权威状态、基础机制和性能保证，脚本负责策略、命令组合与工作流；核心小而聚焦不等于把昂贵计算迁入脚本。

- 自插入、IME、按键解析、布局与渲染等热路径留在 Rust，不同步等待脚本回调。命令派发点可执行有界的同步脚本变换，但不能据此允许昂贵工作阻塞前台；原生基础编辑不依赖脚本运行时参与执行。
- buffer 生命周期、文件 / 进程操作、tree-sitter 解析与查询等新核心能力由 Rust 提供原语，脚本只组合，不另建平行的文本、输入或文件状态体系。
- 脚本通过专门的宿主 API 使用能力，不直接访问核心数据结构、可变引用或 GPUI entity。命令是可执行操作的统一入口，不把数据读取与查询全部伪装成命令；原生与脚本命令遵循 D11 的统一注册来源。
- 所有文本变更仍经过唯一 Edit / 历史入口和输入约束；异步结果绑定目标及版本，迟到结果不能按当前焦点重新解释。扩展执行还须约束任务、队列和资源使用，脚本接入的执行、资源及错误隔离边界见[阶段 D 契约](emacs-fidelity.md#阶段-djs-配置与文本变换)，不视为安全沙箱。
- JavaScript 同时承担用户配置与扩展，运行时采用 rquickjs。配置执行后形成经过 Rust 校验的设置和 keymap；按键查找、布局和绘制读取已生效数据，不反复执行配置脚本。原生命令绑定保留直接执行路径。
- 稳定脚本接口前先明确 buffer / view 所有权和多 view 输入边界；接口随实际功能逐步增加，不提前建设所有未来扩展原语。

配置热重载的难点是副作用的归属与清理，而不是配置对象的嵌套深度。设置 / 键位重载与任意模块、事件订阅、后台任务的卸载应分开设计；本决策不承诺任意脚本可完整热重载。配置重载范围与失败语义见[阶段 D 契约](emacs-fidelity.md#阶段-djs-配置与文本变换)。

## D27 内置语言与通用语法机制

grammar 通过 Cargo 原生内置，增加语言后重新编译；静态定义集中描述语言身份、文件关联、grammar 与查询。Rust 核心统一拥有增量解析、选定的语法分层、查询执行、取消、buffer 共享及快照 / 语言隔离，普通语言接入不逐语言修改 view / 绘制路径。

Markdown 块级、行内和围栏，以及 HTML script / style 使用同一受限范围的解析机制；不另建每语言 worker 或完整 injections 解释器。查询按语言惰性编译复用，没有注入规则的语言不执行额外扫描。子树仅在语言和编辑后的内容范围一致时复用，资源边界与外部行为见 [E2 契约](emacs-fidelity.md#阶段-e2多语言-tree-sitter)。

当前不定义语言包格式、动态原生 / WASM 加载器、安装工具或 JS 语言 API；未来动态语言与 LSP 需按实际需求单独设计，不承诺现有实现零修改兼容。

## D28 Buffer mode 与结构化显示

交互 mode 身份属于共享 buffer，独立于 tree-sitter 语言；命令执行所有者与适用上下文分离。mode 局部键位在配置阶段校验 / 合成，沿用统一命令注册和已有分层查找，运行时输入不调用 JS 判断 mode。身份采用可扩展的命名注册来源，不以封闭 Rust 枚举承诺未来扩展边界；当前不开放 JS mode 注册 / hook / 生命周期。mode 不限于特殊文本查看，也可承载语言编辑策略；JS 应能在受控查询 / 编辑等真实原语具备后实现轻量语言 mode，按实际需求递增 API，不预建完整插件体系。

结构化生成内容仍使用原有 buffer / view / split。buffer 拥有 section 树、可见性和比较会话，view 保留 point / 滚动；显示索引映射真实可见行，不删改正文模拟折叠，也不另建平行 DiffWidget。diff 模型及 Git 行为集中于其模块，通用输入 / 绘制消费 section 与命名样式原语。Git 读取绑定明确 worktree 与 git-dir，刷新不得向父仓库重新发现目标；blob 访问使用完整内容身份。行为见 [F1 契约](emacs-fidelity.md#阶段-f1mode-与只读-magit-diff)。

待确认或延期的工作统一在 [实施计划](plan.md) 维护，不在技术决策中另列待办；决策变更与文档维护遵循 [文档规则](README.md#维护规则)。
