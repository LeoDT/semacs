## 3. R1 编辑视图矩阵

R1 新增正式测量入口，覆盖以下正文形状。样本构造和文件读取是否计入各阶段须明确记录。

| 形状 | 确定性构造 |
|---|---|
| 混合文本 | 第 1 节默认生成样本 |
| 短 ASCII | 每行 127 个 `x` 加 LF，共 65,536 行，8 MiB |
| 短 Unicode | 每行 `λ界🙂` 重复 14 次加 `z` 和 LF，共 65,536 行，8 MiB |
| 长 ASCII | 每行 19,455 个 `x` 加 LF；重复 `ceil(8 MiB / 19,456)` 行 |
| 单条超长行 | 至少一条 8 MiB 无 LF 的 ASCII 正文，并补组合字符 / emoji 变体 |

每种样本分别测量：

- 软换行开启的窗口打开和冷首帧，最终精确布局就绪时间；

- 连续滚动与稳定空帧；
- 窗口改宽、字体 / 字号变化、后台任务完成及过期任务丢弃；
- 按键 / 平台输入到显示更新的延迟。

固定字体、字号、文字区域尺寸、构建模式和运行环境，每项重复至少三次并报告波动。

测量必须确认正文实际装载、滚动真实发生且布局结果正确；不以截断正文、关闭换行或漏绘换取数字。

R1 首轮测量后提出量化预算，经确认固定；未测量或未批准时不写“性能通过”。

### 前台工作边界

- 不同步等待后台全文换行（等待上限为 0）；前台预览限制为 8 KiB 源码扫描，包含 grapheme lookbehind，并限制输出为 viewport 所需行数加 overscan。
  未完成的行不发布为精确索引，余下正文继续后台处理；原文不会截断或自动关闭换行。
- shaping 仅针对可见 / overscan 行，单条行超过 8 KiB 转后台；宽度缓存与内部测量缓存有界。
  稳定帧复用 ShapedRow；大索引释放也放后台。预算字节数不是毫秒承诺，冷字体解析和绘制仍须原生环境测量。
- 版本不兼容的输入几何不可用；旧字体 / 宽度任务和销毁目标的任务不能发布结果。
  此只读基线采集时尚无平台 handler；后续 headless 几何刷新与输入测量见第 6 节。

### 已确认的只读 headless 预算

用户已明确确认以下预算，仅适用于上述固定环境 / release / 六类样本：

## 8. 原生 CPU 绘制 / 平台提交测量入口

正式入口为 `examples/perf_native.rs` 与 `scripts/perf_native.py`。
复用生产 AppShell / BufferView；六类正文与 headless 入口共享
`examples/support/samples.rs`，不另造编辑器或关闭软换行。

`native-profiler` 是显式可选特性，仅打开当前 GPUI 的 profiler，不修改依赖源码或产品默认配置。
程序将正文绘制末尾的小型状态快照，与 GPUI foreground journal 的同一窗口、
同一次 draw / platform submission 按时间区间关联；journal 丢失使整次运行失败。
缓存重放而没有新的绘制快照时仍统计 draw / submit 成本，不伪造新的正文或布局就绪观察。

### 场景与校验

每种样本、每次重复均使用新进程 / 新窗口（进程级字体与 shaping 缓存冷启动，不清空系统 / 驱动缓存）。
文件读取、样本构造和预期正文构造在计时外；复制正文 / 建 Rope 另报 `model_ms`。
初始请求窗口 960 × 640，monospace 16 px / 行高 24 px；窗口管理器可覆盖初始尺寸，
以 CSV 中实际正文宽高为准。测量期间不要操作这些窗口或改变桌面布局。

普通矩阵每份报告 71 行：

- 新窗口首帧与最终完整换行 / 可见 shaping 就绪；
- 30 次各 120 px 的真实 GPUI ScrollEvent 分发，逐次断言滚动位置增加；
- 通过 Window::resize 请求当前窗口宽度的 75%，等待正文宽确实变小；随后改为 monospace bold 18 px / 行高 27 px；
- 30 次强制重绘，随后 30 个无主动 invalidation 的 frame-demand 观察 tick；
  后者只报告是否实际 draw，不是 0 ms 空帧、GPU 帧率或真实空闲功耗；
- 点击滚动区域首个可见行，经 Window::dispatch_keystroke 和已注册 handler 执行插入、后删、换行、合行；
- 同一次前台回调连续分发 32 次插入 / 32 次删除，分别记录整批耗时。
  这不是按固定频率持续输入，也不是 M1 完整命令链。

`--ime` 矩阵每份报告 9 行：初始布局、真实 Pinyin `ni` 预编辑 / Escape 取消，
然后滚动、改宽、改字体、点击，再次预编辑并以 Space 提交 `你`。
使用 Hyprland / wtype / fcitx5，按键间隔固定 1 ms；不会伪造 marked 回调。
每次注入前检查带唯一 token 的测试窗口仍是焦点，不匹配即失败。
有 grim 时保存组合截图；截图在该阶段计时结束后进行，不用于延迟统计。
脚本记录并恢复原焦点、fcitx5 方法和活动状态，检查原始样本 SHA-256 不变。

所有非空正文阶段断言实际绘制有正文、没有空白正文帧、最终显示文本精确、
完整索引覆盖全部显示字节；输入产生 dirty，普通预编辑 / 取消保持 clean。
首帧、临时预览、最终布局分别记录，不通过额外空重绘冒充首帧。

### 字段与边界

所有 `*_ms` 为墙钟毫秒；CPU 侧调用耗时可能含驱动等待，不是 CPU 周期或 GPU 执行时长。

| 字段 | 定义 |
|---|---|
| `action_cpu_ms` | 自动动作的同步分发 / 状态更新耗时，不含后续 draw；外部 IME 的 arm 本身不含输入处理 |
| `draw_cpu_total_ms / max_ms` | 阶段内 GPUI Window::draw 的合计 / 单次最大值，含 render、布局、prepaint、CPU paint |
| `submit_cpu_total_ms` | 同阶段平台提交调用的合计耗时 |
| `first_frame_submit_ms` | 动作开始到第一份场景完成 CPU 平台提交，可能仍是旧字体 / 宽度的保留正文，或中间预编辑 |
| `first_submit_ms` | 动作开始到目标显示文本 / marked 状态和当前布局兼容、且有正文的首次 CPU 平台提交 |
| `ready_submit_ms` | 相同起点到完整索引和可见 shaping 均就绪的那份场景完成 CPU 平台提交 |
| `first_scan_bytes / first_visible_rows / blank_frames` | 首份场景对应的扫描量 / 实际绘制行数，以及阶段内空白正文帧数 |
| `observed_elapsed_ms` | 驱动随后观察完成的总耗时，含观察调度和计时外断言；不是 ready 或输入延迟 |

自动动作使用 `action-to-submit` 边界；真实 IME 使用 `arm-to-submit`：
应用先开始计时并应答 ARMED，脚本再经 IPC、wtype、合成器和 fcitx5 驱动输入。
它包含这些额外开销及固定按键间隔，是该受控流程的耗时，不是实体按键 / IME 回调到屏幕的纯延迟。
没有给实际提交时间再加一个刷新周期来估算呈现时间。

本入口使用的 GPUI profiler API 未提供 GPU timestamp 或 Wayland presentation feedback。
**GPU 执行时间和实际屏幕呈现延迟均明确未测**；on_next_frame 仅用于推进观察，
不作为呈现完成证据。上述 CPU 数据不能代替这两个指标；R1 已按第 9 节的组合证据与用户确认边界验收，不宣称这两项已测。

### 已确认的原生 CPU / 提交流程预算

用户已批准以下独立原生预算，仅针对上述固定环境、六类样本、实际尺寸和 release / profiler 构建；

| 项目 | 已确认上限 |
|---|---|
