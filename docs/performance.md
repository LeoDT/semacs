# 性能基线与测量

当前已有文件层、正文视图与最小输入驱动的可复现样本和测量入口。第 5 / 6 节使用 GPUI 测试平台 / 测试字体，不代表原生字体、GPU 或真实 IME 延迟验收。只读与最小输入驱动 headless 预算均已确认；完整 R1 性能矩阵仍待完成。

## 1. 确定性文件样本

生成器为 `scripts/perf_sample.py`，不依赖 UI 实现，不使用随机数。
默认约 8 MiB，混合 ASCII、CJK、重音 / 希腊 / 俄文、emoji，并每 5000 行插入一条约 19 KiB 的长行。

```sh
python3 scripts/perf_sample.py .pi/tmp/perf-sample.txt
python3 scripts/perf_sample.py .pi/tmp/perf-sample-crlf-bom.txt --crlf --bom
```

| LF / 无 BOM | 8,388,648 | 8,388,648 | 144,632 | 19,212 | 4,881,339 | 325,422 | 1,048,577 |
| CRLF / BOM | 8,388,658 | 8,246,595 | 142,061 | 19,212 | 4,801,640 | 319,635 | 1,029,935 |

本表按换行符切分计行，包含末尾换行后的空段。测量脚本须明确自己的行数口径，不混用 `str::lines()`。

## 3. R1 编辑视图矩阵

R1 新增正式测量入口，覆盖以下正文形状。样本构造和文件读取是否计入各阶段须明确记录。

| 形状 | 确定性构造 |
|---|---|
| 混合文本 | 第 1 节默认生成样本 |
| 短 ASCII | 每行 127 个 `x` 加 LF，共 65,536 行，8 MiB |
| 短 Unicode | 每行 `λ界🙂` 重复 14 次加 `z` 和 LF，共 65,536 行，8 MiB |
| 长 ASCII | 每行 19,455 个 `x` 加 LF；重复 `ceil(8 MiB / 19,456)` 行 |
| 单条超长行 | 至少一条 8 MiB 无 LF 的 ASCII 正文，并补组合字符 / emoji 变体 |

每种样本分别测量：

- 软换行开启的窗口打开和冷首帧，最终精确布局就绪时间；
- 输入、删除、换行 / 合行及局部增量重排；
- 连续滚动与稳定空帧；
- 窗口改宽、字体 / 字号变化、后台任务完成及过期任务丢弃；
- 按键 / 平台输入到显示更新的延迟。

固定字体、字号、文字区域尺寸、构建模式和运行环境，每项重复至少三次并报告波动。
不得以额外无变更 render 代替冷首帧，不得把等待上限当作全文完成时间，也不能只报首帧而隐藏最终就绪耗时。
测量必须确认正文实际装载、滚动真实发生且布局结果正确；不以截断正文、关闭换行或漏绘换取数字。

## 4. 预算与平台边界

R1 首轮测量后提出量化预算，经确认固定；未测量或未批准时不写“性能通过”。
明显的前台全文阻塞或无法解释的回退必须在进入 M1 前解决，不延期到 M3。
M1 补完整命令路径的输入延迟，M3 复测全部相关基线，不能修改预算掩盖回退。

headless 测量用于定位和回归，不代表 Wayland / GPU 帧率。
真实平台的窗口映射、滚动观感、输入和 IME 验收单独记录，并事先征求用户同意。

## 5. 只读视图 headless 基线

正式入口：`examples/perf_view.rs`。它使用正式 AppShell / BufferView，不另建编辑器实现。
固定 GPUI TestPlatform / TestTextSystem（**测试字体、无 GPU、无显示服务器**）、release 构建。
后台任务由测试调度器推进，并非生产线程池调度；这些数字只用于 CPU 回归定位。
每次新建上下文和窗口；正文构造 / 文件读解码在测量外，`model_ms` 单独计入拥有文本的复制及建 Rope。
初始窗口 960 × 640，正文宽 944 px（窗口与 mode line / echo / padding 不计入正文宽），monospace 16 px / 行高 24 px。
改宽测量为窗口 720 × 640；字体测量改为 monospace bold 18 px / 行高 27 px。

```sh
python3 scripts/perf_sample.py .pi/tmp/perf-sample.txt
cargo build --release --example perf_view
RUNS=3 target/release/examples/perf_view .pi/tmp/perf-sample.txt > .pi/tmp/r1-view-perf.csv
```

第 3 节五类正文之外，额外测量无 LF 的 `e + COMBINING ACUTE + 🙂 + x` 重复正文（每组 8 字节，共 8 MiB）。
脚本断言首帧已有正文、最终索引字节与整份正文一致、滚动位置确实变化，且稳定帧不改变布局身份。
`first_ms` 从新窗口创建前开始，到首次正文 paint 完成为止；`ready_ms` 从相同起点到完整 wrap 索引及可见 shaping 就绪。
改宽 / 字体数据同样等到最终就绪，不是前台等待上限。forced frame 是无文本变化但强制重绘 30 次的均值；empty draw 是随后 30 次未主动 invalidation 的 draw 均值。
前者不作为冷首帧，后者不作为 GPU 帧率。统计行数包含 EOF 空行；首帧缓存含一行 overscan。

### 前台工作边界

- 不同步等待后台全文换行（等待上限为 0）；前台预览限制为 8 KiB 源码扫描，包含 grapheme lookbehind，并限制输出为 viewport 所需行数加 overscan。
  未完成的行不发布为精确索引，余下正文继续后台处理；原文不会截断或自动关闭换行。
- shaping 仅针对可见 / overscan 行，单条行超过 8 KiB 转后台；宽度缓存与内部测量缓存有界。
  稳定帧复用 ShapedRow；大索引释放也放后台。预算字节数不是毫秒承诺，冷字体解析和绘制仍须原生环境测量。
- 版本不兼容的输入几何不可用；旧字体 / 宽度任务和销毁目标的任务不能发布结果。
  此只读基线采集时尚无平台 handler；后续 headless 几何刷新与输入测量见第 6 节。

### 已确认的只读 headless 预算

用户已明确确认以下预算，仅适用于上述固定环境 / release / 六类样本：
首帧 ≤ 2 ms；完整初始 / 改宽 / 字体索引就绪各 ≤ 300 ms；
滚动更新 ≤ 1 ms；稳定 forced frame / empty draw 均值各 ≤ 0.25 ms。
这些是后续只读 headless 回归的固定门禁，不代表完整 R1 或真实平台性能通过；不得修改预算掩盖回退。
原生字体、Wayland / GPU 和真实 IME 延迟尚未测量，不能沿用测试字体数字宣布这些项目通过。
输入 / 删除 / 换行 / 合行的首次 headless 测量与已确认预算见第 6 节。

## 6. 最小输入驱动 headless 测量

入口仍为 `examples/perf_view.rs`，在原只读阶段之后追加真实注册 handler 的按键输入测量。
环境、六类约 8 MiB 样本、测试字体 / 调度器和 release 构建同第 5 节；
测量时已经完成改宽 / 字体阶段，即正文宽 704 px、monospace bold 18 px / 行高 27 px。
先点击当前滚动 viewport 的首行左侧，在实际 point 依次输入 `x`、backspace、enter、backspace（合行）。
原文 / 预期字符串构造及内容断言在计时外；每次就绪后再开始下个操作，不是持续输入压力测量。

`front` 从 `Window::dispatch_keystroke` 前开始，包含实际输入分发、Edit、首次更新布局 / paint；
`ready` 从同一起点到完整精确 wrap 索引及当前可见 shaping 就绪。
这是 TestPlatform 的按键到 CPU paint / 就绪时间，不是 GPU 呈现时间。
首次更新断言当前显示身份匹配且同步扫描 ≤ 8 KiB；最终断言文本精确、索引覆盖全部字节且 modified。
同帧连续 IME 回调、几何空窗及临时 / 最终布局后的刷新有正式测试，但本表不测原生 IME 或组合延迟。
