# 性能预算与测量边界

这里维护已批准预算、指标含义与适用条件，不维护执行步骤、实现进度、样本配方或脚本断言清单。
预算适用的固定环境、尺寸与历史数据见 [R1 验收归档](records/r1.md)。

## 适用原则

- 既定预算不通过调宽阈值掩盖回退；环境、样本或构建条件变化时先明确可比性，不直接套用或改写旧结论。
- 基准样本为六类约 8 MiB 正文、软换行开启，复测范围按改动影响选择，不将代表性样本外推为完整矩阵。区分冷首帧与最终完整布局，不能以截断正文、关换行、漏绘或额外热重绘换取数字。
- 各项至少三次，记录波动；原生预算每次运行分别判定，不以平均值掩盖超限。
- 首次使用某字体族 / 字重 / 样式可能触发进程内字体匹配与 shaping 冷路径，不能仅凭发生在某业务动作前就归因于该业务。记录进程是否新建、此前相关字体使用及显式预热；冷路径与缓存复用结果分开，未经计时 / 采样验证只列嫌疑。不能静默预热、删除首次峰值或用热路径替代冷路径预算判定。
- headless 仅用于 CPU 回归，不代表原生字体、GPU 或真实 IME；软件渲染自检与宿主硬件验收分开。
- 显式完整诊断（普通显示或 F1 diff）记录性能超限后继续后续动作及本批获准窗口，避免 setup / 首屏超限遮住后续完整数据；原预算逐项判定，报告始终标记非验收。采集 `completed` 与 `budget_passed` 分开，即使全部合格也不自动转为验收。阶段安全超时只是资源保护，不是放宽后的性能门限；正文 / 几何 / 投影 / 身份错误、异常及安全超时仍停止。

## 指标边界

所有时间为墙钟耗时；CPU 侧可能包含驱动等待，不是 CPU 周期或 GPU 执行时长。

- headless `first` 从新窗口创建前到首次正文 paint，`ready` 到完整换行索引及可见精确 shaping 就绪；全文断点的字素测宽边界见 [排版契约](emacs-fidelity.md#阶段-e3文本样式与高亮合成)；输入 `front` 包含按键分发、编辑与首次布局 / paint，输入 `ready` 使用同一起点。
- 原生 `action_cpu_ms` 是同步动作分发 / 更新，不含后续 draw；draw / submit 是 CPU 调用成本。
- `first_frame_submit_ms` 是首份场景提交，可能仍是旧布局的保留正文；`first_submit_ms` 要求目标文本 / marked 状态及兼容布局，`ready_submit_ms` 还要求完整索引与可见 shaping 就绪。
- 自动动作采用 action-to-submit；真实 IME 采用 arm-to-submit，包含 IPC、wtype、合成器、fcitx5 及固定按键间隔，不是纯实体按键或 IME 回调延迟。
- `observed_elapsed_ms` 包含驱动后续观察及计时外断言，不是 ready 或输入延迟。
- headless forced frame 是无文本变化的强制重绘均值，empty draw 是未主动 invalidation 的 draw 均值；原生 idle 只观察是否实际 draw，不能据此报告 0 ms 帧或空闲功耗。
- 这些入口没有 GPU timestamp 或实际呈现反馈；CPU 提交、候选截图和 on_next_frame 均不证明屏幕呈现完成，也不额外加一个刷新周期估算呈现时间。
- 文件 / buffer 流程从最终确认或补全动作计时，不包含完整路径逐字输入；普通保存、补全与取消可能只报告 UI 观察结果，不自动解释成目标正文提交。文件缓存不受控，不宣称冷磁盘读取。
- `save_ack_before_edit=false` 只说明该键之前尚未观察到保存确认，不证明与实际磁盘 I/O 重叠；短周期 RSS 与 view 释放不证明长期无泄漏或 GPU / allocator 缓存全回收。
- 诊断中的嵌套墙钟区间不能相加作为整帧成本，worker 重叠不证明锁等待；未完成区间保留未完成状态。诊断本身有开销，不将一次诊断替代验收。

## 已确认的 headless 预算

适用于归档中的 TestPlatform / TestTextSystem、release、六类样本及固定尺寸 / 字体。300 ms 来自 R1 首轮实测后确认的工程回归预算，不是编辑器全文排版的行业标准或用户感知阈值；其基线、条件与余量不外推到所有文档、硬件或新增后台任务。首次可见响应与全文 ready 分开判定；预算变更须另行确认。

| 项目 | 上限 |
|---|---|
| 冷首帧 | ≤ 2 ms |
| 初始 / 改宽 / 字体完整索引就绪 | 各 ≤ 300 ms |
| 滚动更新 | ≤ 1 ms |
| 稳定 forced frame / empty draw 均值 | 各 ≤ 0.25 ms |
| 插入 / 后删 / 换行 / 合行 | front ≤ 2 ms；ready ≤ 300 ms |

## 已确认的原生 CPU / 提交流程预算

适用于归档中的宿主硬件、release / profiler、六类样本与实际尺寸。

| 项目 | 上限 |
|---|---|
| 冷打开 | 首次正文提交 ≤ 250 ms；完整布局提交 ≤ 500 ms |
| 单次 CPU draw | ≤ 16 ms，不代表 GPU 帧时间 |
| 插入 / 后删 / 换行 / 合行 | 同步更新 ≤ 2 ms；首次提交 ≤ 16 ms；完整就绪提交 ≤ 300 ms |
| 滚动 / 稳定强制重绘 | 每次首次提交分别 ≤ 4 ms / ≤ 2 ms |
| 改宽 / 字体 | 第一份保留或当前场景提交 ≤ 50 ms；完整新布局提交 ≤ 300 ms；不允许空白正文帧 |
| 同回调 32 次插入 / 删除 | 整批同步更新和首次提交各 ≤ 50 ms；完整就绪提交 ≤ 300 ms |
| 真实 IME 受控流程 | arm 首次目标状态提交 ≤ 75 ms；完整就绪提交 ≤ 300 ms |
| 稳定观察阶段 | 30 个无主动 invalidation 的 frame-demand tick 不产生 draw |

持续输入验收口径（用户于 2026-11-01 确认）：每键同步更新 ≤2 ms、首次目标提交 ≤16 ms；被后续输入取代的旧版本不要求继续完成完整布局，其 ready 保留为未测，不填 0 或计作逐键完成。停止输入后的最终有效版本完整就绪提交须 ≤300 ms，实际观测到的 ready 仍按对应预算判定。该口径明确过期目标的适用范围，不调宽任何数值阈值。

阶段 C 多 view 定向测量口径（用户已确认）：共享 buffer 双 view 下，前台同步动作、选中 view 首次目标提交及完整就绪沿用上述对应动作预算；改宽 / 字体的首份场景与单次 draw / 稳定观察预算同样保留。分别记录选中 view 就绪和同一份场景中全部可见 view 就绪；后者先作为无新增数值门限的聚合基线，不套用旧单 view ready 门限，也不以此宣布多 view 性能整体通过。split / 选择 view 本身仅作基线，冷打开仍按原预算。未解决的聚合性能风险保留在实施计划。

同回调 32 键不是长时间持续输入。GPU 执行 / 实际呈现不属于上述 CPU / 提交流程预算，如需承诺须另行确认测量方案与预算。

文件打开 / 保存、buffer 切换与补全等尚无批准时延门限的新指标只作基线，不擅自套用预载正文冷窗口或单键预算；已有输入与 draw 预算仍按实际覆盖路径判定。

F1 diff 专项同样先作基线：打开、折叠 / 展开、导航、刷新、split 及同场景双 view ready 没有新增数值门限，不套普通正文冷打开 / ready 或单键门限。原生实际覆盖的 CPU draw、垂直滚动首次提交与 idle 沿用既有对应预算。`first_ms` 从最终确认 / 动作分发开始，到目标正文及折叠投影兼容的首次观测；headless 在 draw 后采样，原生取 journal 中经同帧 paint 验证的 CPU 提交终点。`selected_ready_ms` / `all_ready_ms` 分别要求选中 view / 同一场景所有 view 的当前完整索引与可见 shaping 就绪。Git / 解析 / 生成 / 安装和 section spans 是独立诊断区间，不相加推算端到端；磁盘缓存不受控，首次仓库发现与复用 comparison 的打开不可直接等同。显式 diff 完整诊断也覆盖 setup：draw >16 ms、滚动首次提交 >4 ms、idle 产生 draw 均如实标记超限后继续，不以跳过 setup 帧或调宽门限换取通过；idle 即使实际 draw 也不据此填入动作时延。逐帧分段及 CPU 提交仍不代表 GPU / 实际呈现。

F2 status / 单文件写入端到端同样先作基线，不套普通正文 300 ms 或 JS 资源时限；原生绘制 / 滚动 / idle 的适用预算不变。headless `perf_status` 从最终确认或默认键分发开始，到 `run_until_parked` 后显式 draw 观察到目标投影，分别记录选中 / 全部 view 的完整就绪；测试调度器可能合并多个后台完成及 paint，因此首次观测和 ready 相同不证明原生逐帧时序。命令输入 / point 准备在计时外；显式 `probe_draw_max_ms` 不包含调度器内部 paint，不能当作全部 draw 的最大值或用于原生 draw 预算。文件缓存不受控，headless 结果不代替平台字体 / GPU / 实际呈现。
